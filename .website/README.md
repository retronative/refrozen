# reFrozen website

The static project website for reFrozen: Vite + Vue 3 + TypeScript + Tailwind CSS, prerendered to
plain HTML at build time. No server, no runtime data, no tracking.

## Structure

```
.website/
├── index.html              HTML template (head placeholders filled per route by the prerender)
├── vite.config.ts          Vite config; base path from SITE_BASE
├── vercel.json             Vercel build settings
├── plugins/docs.mjs        Vite plugin: ../docs/*.md → `virtual:docs` (HTML + parsed status.md)
├── scripts/
│   ├── site-config.mjs     SITE_BASE / SITE_URL / SITE_CNAME handling
│   ├── slug.mjs            Heading-anchor slugs and doc → route mapping (shared)
│   ├── prerender.mjs       Renders every route, writes 404.html, sitemap.xml, robots.txt, .nojekyll
│   ├── check-links.mjs     Link and anchor checker for dist/ (under SITE_BASE) and docs/
│   ├── check-dist.mjs      Artifact hygiene check for dist/ (file types, private content, third-party requests)
│   ├── check-status.mjs    Fails if a milestone state is written anywhere but docs/status.md
│   ├── check-contrast.mjs  WCAG contrast audit of text colours on the composited surfaces
│   ├── pages-sim.mjs       Local static server emulating GitHub Pages semantics
│   ├── test-routing.mjs    Requests every route (with/without trailing slash) through pages-sim
│   └── og-image.mjs        Renders public/og.png (provisional) with resvg
├── public/
│   ├── favicon.svg         Original mark
│   ├── og.png              Open Graph image, 1200×630 (provisional, generated by og-image.mjs)
│   ├── fonts/              Self-hosted OFL fonts (latin woff2 subsets) and their licence texts
│   └── screenshots/        Rights-reviewed screenshots only (empty until the maintainer chooses)
└── src/
    ├── app.ts, router.ts   App factory, routes and per-route titles/descriptions
    ├── entry-client.ts     Hydration and client-side meta updates
    ├── entry-server.ts     Server render used only by the prerender step
    ├── docs.ts             Access to the docs data
    ├── data/               Site-only content: features, minimap landmarks, screenshot manifest
    ├── components/         Header, footer, minimap, chat log, glyphs, prose renderer, …
    ├── pages/              One lazy-loaded component per route
    └── styles/main.css     Design tokens, textures and all custom styling
```

Routes: `/`, `/features/`, `/screenshots/`, `/docs/`, `/docs/<slug>/`, `/compatibility/`,
`/faq/`, `/releases/`, plus a 404 page.

## How `docs/` is consumed

The repository's root `docs/` folder is the single source of public documentation. The website
never copies it. `plugins/docs.mjs` reads `../docs/*.md` when Vite builds (and watches it in dev),
and exposes the result as the virtual module `virtual:docs`:

- A small front-matter block (`title`, `description`, `order`) supplies the page title, the meta
  description and the order in the docs index.
- Markdown is rendered with markdown-it at build time, so the parser is not shipped to browsers.
  `html: false` escapes any raw HTML in the Markdown and markdown-it's link validation rejects
  `javascript:`/`data:` URLs; that is the sanitisation.
- Headings get stable ids (`scripts/slug.mjs`); relative links such as `faq.md#is-it-legal` are
  rewritten to site routes, so the same files work on GitHub and on the site.
- `compatibility.md`, `faq.md` and `status.md` have dedicated pages (`/compatibility/`, `/faq/`,
  `/releases/`); they are also served at `/docs/<slug>/` with a canonical tag pointing to the
  dedicated page. The FAQ turns each `## question` into an expandable item. Every other doc appears
  at `/docs/<slug>/`.
- **`docs/status.md` is the single source of project status.** The plugin parses its milestone
  table (`State` must be one of `Passed, signed off`, `Passed, sign-off pending`, `In progress`,
  `Future work`; anything else fails the build), its `Planned for v0.1.0` / `Not part of v0.1.0`
  lists and its `release_headline` / `release_planned` front matter. The Releases page, the home
  page's status log and the Features page's milestone labels all read it. `npm run check:status`
  fails if a milestone id appears next to a state word in any other doc or site source.

To add a page, create `docs/<slug>.md` with front matter; it appears in the docs index, the
sitemap and the prerendered output automatically. Only link to other docs with relative `*.md`
links; the link checker rejects links to files outside `docs/`.

## Commands

Run from `.website/` (Node 20.19+ or 22.12+):

```sh
npm ci                 # install the pinned dependencies
npm run dev            # development server with hot reload
npm run build          # vue-tsc type-check, client build, SSR build, prerender into dist/
npm run preview        # serve dist/ locally
npm run check:links    # check internal links/anchors in dist/ and links between docs/*.md
npm run check:dist     # artifact hygiene check of dist/
npm run validate       # build + check:links + check:dist
```

### Configuration

| Variable | Default | Purpose |
|---|---|---|
| `SITE_BASE` | `/refrozen/` | Path the site is served under. The default fits the GitHub project page `https://<owner>.github.io/refrozen/`; use `/` for a custom domain or Vercel |
| `SITE_URL` | `https://retronative.github.io` | Origin for canonical URLs, Open Graph and the sitemap (canonical home: `https://retronative.github.io/refrozen/`) |
| `SITE_CNAME` | unset | Custom domain; when set, `dist/CNAME` is written |

`npm run validate` runs, in order: `check:status`, the `vue-tsc` type-check, the client build, the
SSR build, the prerender (which also validates the screenshot manifest), `check:links`,
`check:dist`, `check:contrast` and `test:routing`:

- **check:links** resolves every `href`/`src` in `dist/**/*.html` as if the site were mounted at
  `SITE_BASE` (a link outside the base fails), checks `#anchors` against the target page's ids,
  flags duplicate ids, checks lazy-chunk and preload references inside the built JS, and checks
  relative links between `docs/*.md`. External links are listed, never fetched.
- **check:dist** is the artifact hygiene gate: only allowlisted file types (html, css, js, svg,
  woff2, txt, xml, json, ico, webmanifest, `CNAME`, `.nojekyll`); raster images only as `og.png`
  (≤ 500 kB) and PNG/WebP directly in `screenshots/` (≤ 1.5 MB each); no source maps; no other
  file over 1 MB; no content that looks private (`reference/` or `game/` paths, work logs,
  internal planning file names, game file names such as `.w3x`/`.mpq`/`.exe`/`.dll`, absolute
  `/Users/` paths, CD-key-like strings); and no third-party runtime requests (external scripts,
  stylesheets, preconnects, CSS `@import`/`url()`, web-font services).
- **check:contrast** computes WCAG contrast for each text colour on the lightest composited value
  of each surface it is used on (page, stone panels, wood header, selection list, banners, the
  hero's river line, the loading plate) and fails below AA.
- **test:routing** starts `pages-sim` and requests every prerendered route in both forms
  (`/refrozen/faq` and `/refrozen/faq/`, likewise `/refrozen` and `/refrozen/`), follows
  redirects, repeats each request (refresh), and checks the status, the final URL (always the
  trailing-slash form), the canonical tag (must be a sitemap URL), and that every referenced
  stylesheet, script, preload, font (via CSS `url()`), lazy chunk and image loads. It also checks
  deep links with `#anchors`, 404s with the site's `404.html` (including wrong-case paths) and
  the Open Graph image.

#### What pages-sim emulates

GitHub Pages' documented behaviour for a project site: the site mounted at `/refrozen/`;
`/refrozen` and any directory without a trailing slash → `301` to the slash form; a directory →
its `index.html`; `/foo` → `foo.html` when present; case-sensitive paths; anything else → the
site's `404.html` with status `404`. It does not emulate CDN caching, HTTPS redirects or custom
domains. **Real GitHub Pages behaviour can only be confirmed after deployment, which needs the
maintainer's approval.** Run it by hand with `npm run pages-sim` (http://localhost:4790/refrozen/).

Validate exactly as CI does:

```sh
cd .website
nice -n 19 npm ci --ignore-scripts
SITE_BASE=/refrozen/ nice -n 19 npm run validate
SITE_BASE=/refrozen/ nice -n 19 npm run preview   # http://localhost:4173/refrozen/
```

## Deploying (prepared only; nothing has been pushed, enabled or deployed)

The output in `dist/` is fully static: one prerendered `index.html` per route, `404.html`,
`sitemap.xml`, `robots.txt`, `.nojekyll` and hashed assets. URLs use trailing slashes (`/faq/`).

### Routing choice

Both `https://retronative.github.io/refrozen` and `https://retronative.github.io/refrozen/` work:
GitHub Pages redirects the directory form without a slash to the slash form, as pages-sim does.
Canonical tags, the sitemap, Open Graph URLs and internal links always use the trailing slash.


History-mode URLs (`/refrozen/faq/`), not hash URLs. Every route is prerendered to its own
`index.html`, so deep links and refreshes are served as real files with their own title,
description, canonical URL and content (good for search engines and link previews, and readable
without JavaScript). `404.html` is the site's not-found page, rendered with base-absolute asset
URLs so it works at any depth; GitHub Pages serves it for unknown paths and the app hydrates it
as the not-found route. Hash routing would have made every page share one HTML document and
broken in-page `#anchors` in the docs.

### GitHub Pages

The workflow is `.github/workflows/pages.yml`:

- Triggers: pushes to `main` that touch `.website/**`, `docs/**` or the workflow, plus manual
  `workflow_dispatch`.
- `build` job (`contents: read`): checkout without persisted credentials, Node LTS with the npm
  cache keyed on `.website/package-lock.json`, `configure-pages`, `npm ci --ignore-scripts`,
  `npm run validate`, then uploads **only `.website/dist`**.
- `deploy` job (`pages: write`, `id-token: write`) in the `github-pages` environment, exposing the
  deployment URL. Top-level `permissions: {}`; `concurrency: pages` without cancelling a running
  deployment. No secrets are used.
- Every action is pinned to a full commit SHA with its version tag in a comment.

To go live (a maintainer decision, not done yet):

1. Repository **Settings → Pages → Build and deployment → Source: GitHub Actions**.
2. Push to `main` (or run the workflow manually). The site appears at
   `https://<owner>.github.io/refrozen/`.

### Custom domain later

1. Set repository variables (Settings → Secrets and variables → Actions → Variables):
   `SITE_BASE=/`, `SITE_URL=https://<domain>`, `SITE_CNAME=<domain>`. The build then writes
   `dist/CNAME`.
2. Configure the domain under Settings → Pages and add the DNS records GitHub documents.

### Vercel (alternative)

Import the repository with Root Directory `.website`, keeping "Include files outside the root
directory in the Build Step" enabled (the build reads `../docs`). `vercel.json` builds with
`SITE_BASE=/`, outputs `dist` and uses trailing slashes; set `SITE_URL` in the project's
environment variables.

### Security notes

- No secrets, tokens or deploy keys; Pages deploys with the short-lived OIDC token
  (`id-token: write`) only in the deploy job.
- Dependencies are pinned exactly and installed from the lockfile with install scripts disabled.
- The site has no runtime data, forms, cookies or analytics. The only third-party request is
  Google Fonts (self-hosting the fonts would remove it).
- Docs Markdown is rendered with raw HTML disabled; `check:dist` guards against publishing
  anything that looks private.

## Asset and trademark policy

- **Everything visual is original**: the textures (SVG noise and turbulence), ornaments, rune-like
  glyphs, the minimap motif, the brand mark and the screenshot placeholder plates are drawn in CSS
  and SVG for this site.
- **No game material**: no Warcraft, DotA, Blizzard or iCCup artwork, logos, icons, fonts,
  screenshots, sounds or game files, and nothing from the repository's `game/` folder. Real
  screenshots are added only after the maintainer approves which images may be published.
- **Nominative use only**: Warcraft III, The Frozen Throne, DotA and iCCup are named only to
  describe compatibility. No look-alike marks. The disclaimer appears in the footer of every page
  and in `docs/disclaimer.md`.
- **Fonts**: Cinzel, Cormorant Garamond and Inter (SIL Open Font License 1.1, no Reserved Font
  Names), self-hosted as latin variable-weight woff2 subsets from the Fontsource 5.3.0 packages,
  with each licence text beside the files in `public/fonts/` (also published). `font-display:
  swap`; no requests to font services or any other third-party origin.
- **Open Graph image**: `public/og.png` is **provisional** (the site's river-split backdrop and an
  original stroke-drawn wordmark, no font involved). Regenerate with `npm run og-image`; replace it
  once a hero art direction is approved.
- **Screenshots**: `src/data/screenshots.ts` is the manifest (file, size, caption, alt text,
  capture context, `rightsReviewedBy`, `rightsReviewedOn`). Only rights-reviewed, actual reFrozen
  gameplay screenshots chosen by the maintainer go there, with files in `public/screenshots/`.
  The build fails if an entry is incomplete or a file is missing. While the manifest is empty the
  page shows original placeholder plates. Images are lazy-loaded with width/height and optional
  `srcset`; each links to the full-size file (no lightbox). The page is currently hidden by
  `SHOW_SCREENSHOTS = false` in `src/data/flags.ts`: unlinked, `noindex` and out of the sitemap,
  but still prerendered at `/screenshots/`. Set it to `true` to restore it everywhere.
- **No private material**: only public summaries written for `docs/` and `src/data/`; nothing from
  the internal `reference/` notes, tools or build output is published.

## Accessibility and motion

Skip link, landmarks, visible focus styles, keyboard-operable navigation and FAQ, and AA contrast
on the dark palette. All decorative motion (loading bar, frost motes, map pings, entrance reveals) is
CSS-only and switched off under `prefers-reduced-motion: reduce`.

The home page's loading-screen entrance is inline (never an overlay; the header and skip link stay
usable). It plays once per browser session (`sessionStorage`, wrapped in try/catch) and can be
skipped with the visible "Skip intro" button, a click or tap on the hero, or a character key; it
never captures Space, arrow, paging, Tab or modifier keys, so scrolling is untouched. Under reduced
motion it starts in its final state. "Continue" then scrolls to the first section.
